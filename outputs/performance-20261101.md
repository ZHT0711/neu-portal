# 2026-11-01 性能与启动页优化

版本：1.0.0+5。沿用现有依赖、接口、登录流程、设置键、日程数据格式与应用标识。

## 修改与原因

1. 服务大厅原来将 shrinkWrap 网格嵌入普通滚动块，首屏就要布局整个应用组。改为带卡片背景的 SliverGrid，应用和专题服务都按可见区域及缓存区创建。
2. 已访问页签原来从透明开始经过 180ms 动画，切回时会显得迟缓。现在立即展示，继续保留页面实例、滚动位置、搜索与分类，并暂停隐藏页的 ticker。
3. 启动层原来结束后由 Stack 改为直接返回首页，导致首页重新挂载。现在固定内容层结构，启动层独立淡出并移除，不重建首页状态。
4. 深色启动页采用当前主题背景、浅色校徽、低对比度边框，去除徽章玻璃模糊和动态光晕。动画播放一次，慢网最迟 850ms 开始淡出，淡出 180ms；系统减少动态效果时跳过。
5. 普通数据刷新不再重新生成整套 ThemeData；主题设置、平台外观偏好及系统动态取色仍生效。
6. 首页与服务页共用的应用磁贴按实际显示像素请求图片解码，减少过大的原始图片解码占用。
7. Android 原生深色启动背景调整为中性暗色，并补齐 Android 12+ 的夜间主题；iOS 原生启动屏通过颜色资源适配系统深浅色和校徽着色。

## 验证

- Flutter 静态分析通过（0 issues）；完整测试套件 51 项通过（原有 38 项 + 新增 13 项）。
- Android / iOS 样式下的压力回归：1000 个应用 + 1000 条专题服务。首屏创建的应用磁贴少于 60 个，滚动后可到达最后一条服务。
- 页签切回首帧无整页透明度动画，页面实例保留，隐藏首页 ticker 关闭；原有搜索状态、大字体与窄屏用例继续通过。
- 深浅色启动层的首页实例只初始化一次，慢网有退出上限，减少动态效果无残留动画，数据刷新复用同一主题对象。
- 已生成并人工检查 Android / iOS 深浅色启动页与服务页的 Flutter 预览，见 `outputs/ui/`。
- Web release 构建通过。
- 本机 Android release 构建受现有 SDK 环境阻碍：配置目录只有 platform-tools，缺少 NDK 28.2.13676358 及已接受的许可证。Android APK 与 iOS IPA 由推送后现有 GitHub Actions 构建。

这些检查验证了布局工作量和状态行为，不是手机上的帧耗时测量。Windows 无法执行 Xcode 构建；iPhone 的原生启动屏、液态玻璃和实际切页帧率仍需真机验收。

## 复现
